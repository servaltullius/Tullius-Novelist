# 설계 초안 v0.1 Codex 교차 검토 정리 (2026-11-06)

- 검토 모델과 설정: Codex gpt-6-astra, 추론 high, files 모드. Codex가 근거 파일을 셸로 직접 읽었다.
- 실행 결과: 셸 명령 21회, 웹 검색 7회, 파일 변경 0건, 785초
- 원문: [codex-design-review-v0.1-raw.md](codex-design-review-v0.1-raw.md)
- Codex의 판정: v0.1은 본 구현 착수 보류. 방향은 유지하되 다섯 가지를 먼저 문서로 확정해야 한다.

## Claude가 직접 다시 확인한 사실

| 주장 | 확인 결과 |

## 분류

번호는 Codex 원문의 지적 번호다.

| 번호 | 주제 | 분류 | v0.2 반영 |
|---|---|---|---|
| 1 | 세이브 확정·복구 프로토콜 없음 | 수용 | 5.3 세이브 처리: co-save 쓰기 결과에 따라 확정과 보류를 나눈다. .ess의 성공은 알 수 없다고 명시했다. |
| 2 | flush 타임아웃 때 다음 조각으로 넘김 | 수용 | 세이브 콜백이 기다리지 않는 비동기 봉인(seal)으로 바꿨다. 사건이 어느 세이브에 속하는지는 cutoff seq로 고정한다. |
| 3 | revert와 메인 메뉴를 포함한 상태표 없음 | 수용 | 5.2 상태 기계를 넣었다. `coc` 시작은 0단계 시험 항목으로 남겼다. |

| 8 | 큐 포화 시 중요 사건 보호 | 수용 | 등급별 한도, 제어 경로 분리, 유실 구간 기록, 바이트 상한 |

반대한 지적은 없다. 반대 근거를 찾으려고 확인한 사실(위 표)이 모두 Codex의 주장을 뒷받침했다. 42번만 Codex가 놓친 `ItemCrafted` 이벤트로 보완했다.

## Codex가 보지 못한 맥락

- 사용자가 확정한 결정(게임 안 무간섭, 세이브 단위 기록, 작가 키트 등)은 묶음에 적었다. 그래서 Codex는 이 결정을 뒤집자는 지적은 하지 않았다.
- 툴챈 소개 글과 이름 결정 과정은 넣지 않았다. 설계 판단과 관계없다.
