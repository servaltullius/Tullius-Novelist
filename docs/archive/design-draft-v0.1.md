## 1. 목표

스카이림 플레이를 자동으로 기록하고, 사용자가 이미 결제한 AI 구독(Claude, ChatGPT, Gemini)으로 그 기록을 **한국어 장편 소설**로 만든다. 완성된 장은 게임 안에서 책으로 읽는다.

### 지켜야 할 원칙

1. **게임 안에서 플레이어를 귀찮게 하지 않는다.** 장 나누기, 메모 입력, 확인 창, 선택지를 넣지 않는다. 설정 화면은 예외다.
2. **일지가 아니라 소설이다.** 장을 나누고, 사건을 고르고, 각색하는 일은 AI가 한다. 코드가 만든 요약은 AI에게 주는 재료일 뿐, 사용자에게 보여 주지 않는다.
3. **기록 도구는 AI를 부르지 않는다.** 구독 앱도 몰래 실행하지 않는다. 사용자가 자기 구독 앱에서 대화로 시키고, 그 앱의 모델이 우리 로컬 도구를 부른다. 예외는 9장의 선택 기능(OpenAI 공식 경로) 하나뿐이다.
4. **사실은 바꾸지 않는다.** 기록에 없는 사건, 인물, 사망을 지어내지 않는다. 표현만 각색한다.
5. **세이브 계보를 따른다.** 예전 세이브를 불러와 다시 한 진행이 정사(正史)가 되고, 버린 진행은 본편에서 빠진다.
6. **게임 안정성이 먼저다.** 게임 스레드에서는 네트워크, 무거운 파일 작업, 긴 계산을 하지 않는다.

### 하지 않는 것

- NPC와의 AI 대화나 NPC 기억 시스템. 이 영역은 SkyrimNet과 CHIM이 다룬다.
- 게임을 하는 도중에 실시간으로 소설을 생성하는 것. 9장의 선택 기능에서만 고려한다.
- 원시 로그나 일지를 화면에 보여 주는 기능. 이 영역은 Chronicle ChatBox가 다룬다.

## 3. 전체 구조

```
┌──────────── 게임 프로세스 ────────────┐
│ TulliusNovelist.dll (SKSE)            │
│  ├ 이벤트 싱크 → 큐 → 쓰기 스레드 ──────┼──▶ 기록 저장소 (파일)
│  ├ co-save: 캐릭터 ID, 세이브 ID, 부모 ID │        ▲      │
│  └ 읽기 화면 ◀──── 완성된 장 ───────────┼────────┼──────┘
└───────────────────────────────────────┘        │
                                                 │ 읽기/쓰기
┌──────── 사용자의 구독 앱 ────────┐   MCP stdio  │
│ Claude Code / Codex / Antigravity │◀──────────▶ TulliusNovelist.exe (C#)
│ "내 이야기 이어서 써 줘"            │            ├ mcp      : 작가 키트 도구
└───────────────────────────────────┘            ├ export   : 채팅 첨부용 파일
                                                 └ import   : 채팅 결과 들여오기
```

- **DLL**: 기록하기, 세이브 계보 관리, 완성된 장 표시만 맡는다. 요약이나 압축은 하지 않는다.
- **EXE**: 게임이 꺼져 있어도 동작한다. 압축, 중요도 판정, 패키지 만들기, 검증, 저장을 맡는다. 툴리우스 번역기의 MCP 서버, 한국어 후처리, TM·게임 사전 코드를 재사용하려고 C#으로 만든다.
- **기록 저장소**: `%USERPROFILE%\Documents\My Games\Skyrim Special Edition\TulliusNovelist\`
  - GOG판은 `Skyrim Special Edition GOG` 폴더를 쓴다.
  - MO2의 Data 가상화 밖이라서, 모드 목록이 바뀌어도 기록이 남는다.
  - MO2가 이 경로를 그대로 두는지는 0단계에서 확인한다.
  - EXE는 DLL이 남긴 위치 파일을 읽어서 경로를 찾는다. 경로를 하드코딩하지 않는다.

### 4.2 스레드 구조

1. **이벤트 싱크**는 플레이어나 동료와 관련 있는지만 먼저 확인한다. 필요한 값(문자열, ID)을 **복사**해서 큐에 넣고 바로 돌아온다.
   - 이벤트 소스는 spin lock을 잡은 채 동기로 호출하므로, 여기서 시간을 쓰면 게임이 멈춘다.
   - 게임 객체 포인터는 큐에 넣지 않는다.
2. **큐**는 용량 제한이 있는 MPSC 큐다. 가득 차면 우선순위가 낮은 사건(전투 세부 등)을 합치거나 버리고, 버린 개수를 기록한다.
3. **쓰기 스레드**는 큐를 비워서 `pending-<sessionId>.jsonl`에 줄 단위로 덧붙인다. 게임이 갑자기 꺼져도 진행분이 남는다.
4. 게임 자료를 조회해야 하는 부분(표시 이름, 저널 텍스트)은 싱크 안이나 `SKSE::GetTaskInterface()->AddTask`에서 처리한다. 쓰기 스레드에서는 게임 객체를 만지지 않는다.
5. 세이브 콜백(게임 스레드)은 쓰기 스레드의 flush를 기다린다. 그러니 쓰기 스레드는 절대로 게임 스레드를 기다리지 않아야 한다. 그래야 서로를 기다리는 교착이 생기지 않는다.

### 4.3 성능 기준 (0단계에서 측정)

다음 항목을 측정한다.
- 싱크 처리 시간 p50/p95/p99
- 초당 사건 수
- 큐 최고점과 버린 개수
- 세이브 콜백이 추가로 걸리는 시간
- 프레임 타임 변화

목표는 싱크 p99가 50µs 이하, 세이브가 추가로 걸리는 시간이 10ms 이하다. 이 숫자는 측정 전에 정한 목표치일 뿐 보장값이 아니다.

## 5. 세이브 계보

### 5.1 식별자

| 이름 | 생성 시점 | 저장 위치 |
|---|---|---|
| `characterId` | 새 게임을 시작할 때, 또는 우리 기록이 없는 세이브를 처음 불러올 때 (UUID) | co-save |
| `saveUid` | 세이브할 때마다 (UUID) | co-save, 조각 파일 이름 |
| `parentSaveUid` | 세이브할 때, 그 시점의 `currentParent` | co-save, 조각 파일 머리말 |
| `schemaVersion` | 고정값 | co-save, 모든 파일 |

co-save에는 이 식별자만 둔다. 사건 자체는 외부 파일에 있다.

### 5.2 상태 흐름

| 상황 | 처리 |
|---|---|
| 새 게임 (`kNewGame`) | `characterId`를 새로 만들고 `currentParent = null`로 둔다. 새 pending 파일을 연다. |
| 세이브 (save callback) | 1. 쓰기 스레드에 flush를 요청하고 끝날 때까지 기다린다(대기 시간 상한을 둔다). 2. `newUid`를 만든다. 3. pending 파일을 `segments/<newUid>.jsonl`로 원자적으로 바꾼다. 머리말에는 부모 ID, 게임 시각, 세이브 이름을 넣는다. 4. co-save에 식별자를 쓴다. 5. `currentParent = newUid`로 두고 새 pending 파일을 연다. |
| 로드 (`kPreLoadGame`) | 지금의 pending 파일을 닫고 "로드 대기" 상태로 둔다. 아직 옮기지 않는다. 세대 번호를 올려서, 로드 도중이나 이전 세대에서 늦게 도착한 사건을 버린다. |
| 로드 (co-save load callback) | 식별자를 읽어서 임시로 보관한다. 아직 확정하지 않는다. |
| 로드 성공 (`kPostLoadGame`, 성공 값 확인) | 1. "로드 대기" pending 파일을 `discarded/`로 옮긴다. 이것이 버려진 진행이다(외전 재료). 2. `currentParent = saveUid`로 확정한다. 3. `character.json`의 `activeHead`를 이 세이브로 갱신한다. 4. 새 pending 파일을 연다. 5. 읽기 화면에 "이 계보의 장" 목록을 다시 불러오라고 알린다. |
| 로드 실패 | "로드 대기" 파일을 pending으로 되돌리고 이전 상태를 유지한다. |
| 우리 기록이 없는 세이브 (모드를 중간에 설치) | `characterId`를 새로 만들고 `parent = null`로 둔다. "기록 시작 시점" 정보로 레벨, 완료된 퀘스트 목록, 현재 장소를 한 번 수집한다(프롤로그 재료). 한계가 있다. 기록이 없는 같은 캐릭터의 세이브를 여러 개 따로 불러오면 캐릭터가 여러 개로 나뉜다. 나중에 EXE에 "캐릭터 합치기" 도구를 둔다. |
| 조각 파일이 없음 (폴더 삭제 등) | 남아 있는 조상까지만 이어 쓴다. 끊긴 지점은 `status`가 경고로 알린다. 다른 캐릭터에 자동으로 잇지 않는다. |

- 자동 저장, 빠른 저장, 종료 시 저장 모두 같은 경로를 탄다. 빠른 저장 파일이 덮어써져도 ID 사슬은 끊기지 않는다.
- 세이브 콜백이 끝난 뒤 .ess 쓰기가 실패하는 경우도 있다. 그러면 조각만 남는데, 다음 세이브의 부모가 그 조각을 가리키므로 사슬은 그대로 유지된다.

### 5.3 정사와 장 표시

- 세이브 S의 이야기는 S에서 시작해 부모를 따라 맨 처음 조각까지 거슬러 올라간 **조상 사슬**이다.
- 장은 자신이 다룬 사건 범위(시작 조각·seq, 끝 조각·seq)를 기록한다.
- 세이브 S를 불러왔을 때, 장의 끝 조각이 S 자신이거나 S의 조상이면 그 장을 보여 준다. 나머지 장은 "다른 세계선"으로 보관하고 숨긴다.
- 확인할 시험 경로: A 저장 → B 진행 → A 로드 → C 진행 → B 로드. 이 외에 co-save 누락, 조각 누락, 로드 실패, 생성 중에 로드하는 경우, 저장 직후 강제 종료하는 경우도 시험한다.

```
    chapters/<chapterId>.json
    author/<chapterId>.json  # 그 장을 쓴 뒤의 작가 상태(인계 노트)
    glossary.json           # 고유명사 표기(원문=한글), 출처(조회/모델)
    settings.json           # 문체 프리셋, 성인 옵션, 언어
```

- 모든 파일은 UTF-8이다. 쓸 때는 임시 파일에 쓴 뒤 이름을 바꾸는 방식으로 원자적으로 쓴다.
- DLL이 쓰는 파일(segments, pending, discarded)과 EXE가 쓰는 파일(chapters, author, glossary)을 나눈다. 같은 파일을 두 프로세스가 쓰지 않는다.
- `character.json`은 DLL이 쓰고 EXE는 읽기만 한다. `settings.json`은 EXE가 쓰고 DLL은 읽기만 한다.

**장 파일(`chapters/*.json`)의 필드**
- 장 번호, 제목, 제사(인용문), 문단 배열
- 다룬 사건 범위
- 문체 프리셋
- 생성한 앱과 모델(사용자가 알려 준 값)
- 생성 시각, 입력 해시

**작가 상태(`author/*.json`)의 필드**
- 주인공 기질 키워드 3개, 주력 전투 감각, 최근 내면 변화
- 인물 관계(동료와 관계 온도)
- 미회수 복선 목록
- 다음 장의 "이어 쓸 지점"

## 7. 작가 키트와 MCP 서버 (TulliusNovelist.exe)

### 7.1 사용 흐름

1. 사용자가 `novelist-kit` 폴더를 구독 앱에서 연다.
   - Claude Code: 작업 폴더로 선택
   - Codex: 작업 폴더로 열기
   - 안티그라비티: 워크스페이스로 열기 (처음 한 번 `안티그라비티 연결.cmd` 실행)
2. "내 이야기 이어서 써 줘"라고 말한다.
3. 앱의 모델은 다음 순서로 진행한다.
   - `status`
   - `next`, 장 쓰기, `submit`을 반복
   - 끝나면 보고
4. 사용량 한도에 걸려 멈추면, 다음에 "이어서 써 줘"라고 하면 된다. 모든 상태는 저장소에 남아 있다.

키트 구성은 번역기의 agent-kit을 따른다.
- `AGENTS.md`(본문), `CLAUDE.md`, `GEMINI.md`(본문을 가리킴)
- `.mcp.json`, `.codex\config.toml`
- `안티그라비티 연결.cmd`, `사용법.txt`

### 7.2 도구

| 도구 | 인자 | 하는 일 |
|---|---|---|
| `guide` | 주제 | 안내 파일 내용을 준다. 셸이 막힌 앱도 읽을 수 있게 하기 위해서다. |
| `status` | (캐릭터) | 캐릭터 목록, 현재 계보의 머리(가장 최근 세이브), 쓴 지점, 아직 안 쓴 분량(사건 수, 예상 글자 수), 계보가 끊긴 곳, 대기 중인 요청 |
| `next` | 캐릭터, (머리 세이브) | 아직 안 쓴 구간의 **장 패키지**를 만든다. 내용은 작가 지침, 문체 프리셋, 주인공 프로필, 직전 작가 상태, 압축된 사건 목록, 고유명사 목록이다. 한 번에 넘기는 분량에는 상한을 둔다. |
| `submit` | 요청 ID, 장 배열(번호, 제목, 제사, 문단), 작가 상태, 쓴 지점 | 검증(7.4) 후 저장한다. 실패하면 이유를 돌려주고 모델이 다시 제출한다. 성공하면 다음 요청 여부를 알려 준다. |
| `lookup` | 낱말 배열 | 고유명사의 한국어 표기를 찾는다. 7.5의 순서를 따른다. |
| `show` | 장 번호 | 이미 쓴 장을 보여 준다. |
| `revise` | 장 번호, 문단 수정 | 이미 쓴 장을 고친다. 사건 범위는 바꾸지 않는다. |
| `style` | 프리셋 | 문체를 바꾼다. 다음 장부터 적용된다. |
| `sidestory` | 버려진 분기 ID | 외전 패키지를 만든다. 사용자가 요청할 때만 쓴다. |

**머리 세이브 고르기**
- 게임이 꺼져 있으면 사용자가 어느 세이브에서 이어 할지 알 수 없다.
- "가장 최근 세이브"를 머리로 고르면 틀릴 수 있다. B에서 저장한 뒤 A를 불러와 C를 진행하다가 저장하지 않고 껐다면, 가장 최근 세이브는 버린 B다.
- 그래서 기본값은 `character.json`의 `activeHead`로 한다. 마지막으로 저장했거나 불러온 세이브다. 위 예에서는 A가 된다.
- 다른 세이브는 인자로 지정할 수 있다.
- 장 번호는 계보 안에서 이어진다. 그래서 세계선이 다른 두 장이 같은 번호를 가질 수 있다. 장 ID는 고유하다.

**압축과 중요도** (`next` 안에서 처리)
- 1순위는 장면으로 쓴다.
  - 이름 있는 NPC나 동료의 사망
  - 퀘스트 완료·실패
  - 팩션 가입
  - 첫 드래곤 영혼
  - 대도시에 처음 들어감
  - 동료 합류·이별
  - 플레이어의 출혈 상태
- 2순위는 연결용 요약으로 쓴다. 보스급 처치, 희귀 장비, 새 지역 발견이 여기에 든다.
- 3순위는 묶어서 몽타주로 쓴다. 일반 전투, 채집, 제작, 거래가 여기에 든다.
  - 예: "늑대 4, 산적 3 처치(12분간), 철 단검 18회 제작"
- 같은 종류의 사건이 연달아 나오면 하나로 합친다. 전투는 시작부터 끝까지 한 덩어리로 만들고 지속 시간, 출혈 여부, 상대 수를 붙인다.
- 성인 사건은 8장 규칙에 따라 패키지를 만들 때 바꾸거나 뺀다.

### 7.3 작가 지침

- 바탕은 Gemini 초안의 "작가 지침서"다. 검토 문서의 보완 사항을 반영한다.
  - 출력은 구분자 대신 `submit` 인자로 받는다.
  - 인계 노트는 도구 DB에 저장한다.
  - 고유명사는 조회 결과를 우선한다.
- 기본 문체는 3인칭 제한 시점의 하드보일드다. 선택 문체는 동료의 수기, 후대 학자의 평전, 야전 일지, 음유시인이다.
- 성인 사건이 들어 있는 패키지에만 조건부 지침 블록을 붙인다.
- 지침 원문은 키트의 `guide`와 패키지 양쪽에서 같은 파일을 쓴다(한 곳만 고치면 된다).

### 7.4 `submit` 검증

**거부하는 경우 (저장하지 않음)**
- 필수 필드 누락, 빈 문단
- 장 번호가 이어지지 않음
- 쓴 지점이 패키지 범위를 벗어남
- 요청 ID나 입력 해시가 다름. 그 사이에 기록이 바뀐 경우다.

**경고만 하는 경우 (저장은 하되 모델에게 고치라고 알림)**
- 본문에 알파벳이 있음 (로어 사전에 있는 예외는 허용)
- 금지어가 있음
  - 게임 용어: 레벨, 퀘스트, 스태미나 등
  - 무협 한자어, 현대 외래어
  - 번역투 대명사가 문단마다 반복됨
- 고유명사 단어장과 다른 표기가 나옴
- 기록에 없는 고유명사로 보이는 낱말이 있음. 한국어 문장에서 이것을 자동으로 찾는 방법은 아직 정하지 않았다. 처음에는 단어장과 로어 사전에 없는 "이름 패턴"만 경고한다.

**후처리**
- 한국어 조사를 바로잡는다. 번역기의 `KoreanTranslationFixer`를 재사용한다.

### 7.5 고유명사 표기 순서

1. 런타임에 기록된 표시 이름. 사용자 로드오더의 번역 모드가 이미 적용된 이름이다.
2. 프로젝트 단어장(`glossary.json`)
3. 툴리우스 번역기의 내장 TM과 게임 사전(한국어 패치)
4. 위에 모두 없을 때만 모델이 정하고, 그 결과를 단어장에 고정한다(출처: 모델).

### 7.6 대체 경로: 채팅에 첨부

- `TulliusNovelist.exe export`: 장 패키지와 작가 지침을 마크다운 파일 하나로 만든다. 사용자는 이 파일을 ChatGPT, Claude, Gemini 웹 채팅에 첨부한다.
- 이 경로에서는 구분자 형식(`=== [장 시작] ===` 등)으로 답을 받는다.
- `TulliusNovelist.exe import <결과 파일>`: 결과를 해석하고 `submit`과 같은 검증을 거쳐 저장한다.
  - 일반 사용자용으로 키트에 `가져오기.cmd`를 둔다. 결과 파일을 그 위에 끌어다 놓으면 된다.
  - 폴더를 감시해서 자동으로 들여오는 방식은 쓰지 않는다. EXE가 항상 켜져 있지 않고, DLL은 결과를 해석하지 않는다.
- 들여오지 않아도 다음 패키지는 만들 수 있다. 다만 작가 상태가 없으므로, 코드가 만든 사실 요약으로 연속성을 대신한다.

## 8. 성인 콘텐츠

- 옵션: `제외`(기본) / `암시만`
  - "그대로"는 제공하지 않는다. AI 서비스가 생성하지 않기 때문이다.
- **본체에는 성인 관련 코드가 없다.** 대신 범용 공개 API를 둔다.
  - 다른 모드가 이야기 사건을 보낼 수 있는 ModEvent `TulliusNovelist_Event`다. 종류, 상대, 장소, 시간 경과를 받는다.
  - 성인 어댑터도, 퀘스트 모드 제작자도 이 API를 쓴다.
- 감지는 선택 설치하는 **성인 어댑터**(ESL 하나와 Papyrus)가 맡는다. 어댑터가 중립 사건으로 바꿔서 본체 API로 보낸다.
  - **SexLab P+**: `AnimationStart`/`AnimationEnd`(thread ID는 `strArg`)를 받는다. 시작할 때 `GetThread(id).GetPositions()`로 참여자를 조회한다.
  - **OStim NG**: `ostim_thread_start`(`numArg` = threadID), `ostim_thread_end`. 미설치 상태라 실행 검증을 못 했다.
  - 장면 식별자는 계보, 세션, 프레임워크, threadID, 세대 번호를 묶어 만든다.
- 어댑터가 보내는 형태는 중립 기호뿐이다. 예: `[친밀한 시간: 상대=세라나, 장소=여관, 시간 경과=7시간]`
  - 애니메이션 이름, 태그 같은 원문은 본체에 오지 않는다.
- 전투 패배 직후에 일어나는 장면처럼 합의 여부가 불분명한 맥락은, 기록 단계에서 성적 요소 없이 `[패배: 포로가 됨]`으로만 남긴다.
- `제외` 옵션이면 패키지를 만들 때 해당 사건을 빼고, 시간 경과만 남긴다.
- 배포 형태는 본체(일반 등급)와 성인 어댑터(별도 파일, 성인 등급)로 나눈다. Nexus 정책에서 분리가 의무인지는 확인되지 않았다. 그래도 안전한 쪽을 택한다.

## 9. 선택 기능: OpenAI 자동 생성 (나중 단계)

- 공식 경로는 OpenAI SIWC의 "ChatGPT plan usage"(오픈소스·로컬 앱용, preview)다.
  - OAuth PKCE와 127.0.0.1 루프백을 쓴다.
  - 자격 증명은 EXE가 소유자 전용 경로에 저장한다.
- 켜면 게임을 끌 때나 세이브 후 일정 시간이 지났을 때 EXE가 백그라운드에서 `next`와 `submit`을 직접 돈다. 모델 호출은 Responses API를 쓴다.
- 이 기능은 원칙 3의 유일한 예외다. 사용자가 직접 켜고 로그인해야만 동작한다.
- 착수하기 전에 확인할 것이 세 가지 있다.
  - SIWC 약관 원문 (아직 403이라 읽지 못했다)
  - "open-source partners"가 별도 승인이 필요하다는 뜻인지
  - Plus 플랜의 5시간 한도 공유 영향
- Claude는 회색지대이고 Gemini는 약관상 금지라서, 이 기능을 제공하지 않는다.

## 11. 단계

각 단계의 "완료" 기준은 실제 게임이나 실제 앱에서 확인한 결과로 판단한다. 빌드가 성공한 것만으로는 완료가 아니다.

**0단계. 검증 실험** (각각 작은 시험 플러그인이나 스크립트)
1. MVP 이벤트가 실제로 발화하는지 본다. 반복 퀘스트, 별칭 치환 목표, 중지와 완료, 사망과 출혈을 화면과 대조한다.
2. co-save 계보를 본다. 5.3의 시험 경로를 모두 돌린다.
3. MO2 환경에서 Documents 저장소 경로가 실제 어디로 가는지 본다.
4. 책 메뉴에 한글 1만, 5만 자를 넣고 Prisma 읽기 화면에 같은 분량을 넣어 본다. 닫힌 상태의 비용도 잰다.
5. 수작업으로 만든 장 패키지 하나를 세 앱(Claude Code, Codex, 안티그라비티)에 주고 시간, 사용량, 품질, 지침 위반 수를 기록한다.

**1단계. 기록기**: DLL에 MVP 사건, 큐와 쓰기 스레드, 세이브 계보, 저장소를 만든다.
- 완료 기준: 2시간 플레이에서 프레임 저하와 CTD가 없다. 계보 시험을 통과한다. 성능 수치가 4.3 목표 안에 든다.

**2단계. 작가 키트**: EXE에 MCP 서버, 도구, 압축, 검증, 지침 v1, 키트 폴더를 만든다.
- 완료 기준: 세 앱에서 실제 기록으로 3장 이상을 쓰고 저장한다. 되감은 세이브에서 이어 쓰면 올바른 계보를 따른다.

**3단계. 게임 안 읽기**: 읽기 화면, 새 장 알림, 미읽음 표시, 다른 세계선 숨김을 만든다.

**4단계. 넓히기**: NPC 자막, 제사, 문체 프리셋, 외전, 채팅 첨부 경로(`export`/`import`), 성인 어댑터를 추가한다.

**5단계. 배포**: Nexus 페이지, AI 사용 표기, GPL 소스 공개, 사용법, 툴챈 공지를 준비한다.

**6단계 (선택)**: OpenAI SIWC 자동 생성

## 12. 위험

| 위험 | 대응 |
|---|---|
| 이벤트의 의미가 실제 플레이와 다름 (중지와 완료 혼동, 빈 payload) | 0단계에서 화면과 대조한다. 의심스러운 사건은 "추정"이라고 표시해서 패키지에 넣는다. |
| 세이브 콜백이 길어져서 세이브가 지연됨 | 쓰기 스레드가 계속 덧붙이고, 세이브 때는 flush와 이름 변경만 한다. 대기 시간 상한을 넘으면 다음 조각으로 넘긴다. |
| 기록에 없는 사건을 모델이 지어냄 | 지침과 `submit` 검증을 둔다. 장마다 다룬 사건 범위를 저장해서 되짚을 수 있게 한다. |
| 구독 사용량 한도 때문에 긴 기록을 한 번에 못 씀 | 패키지 분량에 상한을 두고, "이어서 써 줘"로 이어 한다. |
| 앱마다 동작이 다름 (도구 지연 로딩, 허락 창, 셸 실패) | 번역기에서 얻은 해법을 그대로 쓴다: `guide` 도구, 리소스, 전역 등록 스크립트. |
| AI 서비스 정책 때문에 장 전체가 거부됨 | 성인과 폭력 지침은 해당 장에만 붙인다. 거부되면 그 구간을 보류로 남기고 다음으로 넘어간다. |
| 약관이나 요금제가 바뀜 | 원칙 3을 지킨다. 배포 전에 앱별 조건을 다시 확인한다. |
| Nexus의 AI 표기와 원문 사용 권한 | 기능, 외부 처리, AI 사용을 페이지에 정확히 공개한다. 다른 모드의 대사 원문은 짧게 인용하는 수준으로 제한하는 옵션을 둔다. |
