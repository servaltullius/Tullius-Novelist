너는 Skyrim SE/AE SKSE 플러그인 조사 담당이다. 코드를 수정하지 말고 읽기 전용으로 조사해서 보고해라.

[배경]
게임 진행을 감지해서 장편 소설로 바꾸는 SKSE 모드를 설계하기 전이다. 구조는 3단이다.
1) 코드만으로 만드는 게임 내 모험 일지(AI 없음)
2) 장이 끝나면 "장 패키지" 프롬프트를 클립보드로 내보내고, 사용자가 ChatGPT/Claude/Gemini 구독 채팅에 붙여넣은 뒤 결과를 다시 들여온다
3) SKSE 플러그인이 백그라운드에서 사용자가 로그인해 둔 공식 CLI(claude -p, codex exec, gemini)를 실행해서 자동으로 생성한다
게임 스레드에서 네트워크 통신은 하지 않는다.

배포: Nexus Mods 공개가 목표이고, 어려우면 국내 커뮤니티(툴챈) 배포로 간다.
성인 콘텐츠: 지원하되 사용자가 선택할 수 있어야 한다(예: 제외 / 암시만 / 그대로).

개발 환경: 게임 1.6.1170, CommonLibSSE-NG(alandtse ng), 한국어 번역 환경(STRINGS 파일 한글), 활성 플러그인 약 4250개.
설치된 관련 모드: Prisma UI 1.5.1, SKSE Menu Framework 3.8(한글 폰트 INI 수정본), SexLab Framework P+ 2.17.1 NG. OStim은 미설치.
로컬 CommonLibSSE-NG 헤더: G:\skyrim project\스카이림 락픽 모드\external\CommonLibSSE-NG\include\RE

[조사 항목]
1. 이벤트 소스 표: 아래 각 항목을 CommonLibSSE-NG에서 어떻게 구독하는지 정리해라.
   (이벤트 타입, 소스를 얻는 방법, 구조체 필드, 헤더 경로:줄)
   - 퀘스트 시작·종료·스테이지 변경, 목표 표시·완료(ObjectiveState), 저널 로그 갱신
   - 지역 발견·클리어·이동·빠른 이동, 레벨업, 스킬 상승, 책 읽기, 드래곤 영혼, 단어·주문 습득
   - 전투 시작·종료, 사망(누가 누구를), 출혈 상태 진입, 중요한 아이템 획득
   - 범죄·현상금, 결혼·동료 영입 등 관계 변화를 잡을 수 있는 경로가 있는지
   - 다른 모드의 SKSE ModEvent를 C++에서 받는 방법(ModCallbackEvent 등)

2. 표시용 텍스트 추출
   - 퀘스트 표시 이름, 현재 목표 텍스트(별칭 치환이 끝난 문자열), 스테이지 로그 엔트리 텍스트를 런타임에 얻는 API와 필드
   - 저널에 실제로 표시되는 퀘스트와 시스템 퀘스트를 구분하는 기준
   - 대화: 플레이어가 고른 대사와 NPC 응답 자막을 잡는 방법(DialogueMenu, MenuTopicManager, SubtitleManager, TESTopicInfo 등). 훅이 필요하면 후보 함수, Address Library ID, 위험도

3. 한국어
   - 한국어 STRINGS 환경에서 BSFixedString / GetFullName이 반환하는 바이트가 UTF-8인지 CP949인지. 근거가 없으면 검증 방법을 제안해라.
   - 은/는, 이/가 같은 조사를 받침으로 자동 선택할 때, 영어로 남아 있는 이름이나 숫자로 끝나는 이름을 어떻게 다루는지 일반적인 해법

4. 세이브 분기
   - SKSE co-save에 체크포인트 ID를 저장해서, 예전 세이브를 불러오면 이벤트 타임라인을 되감는 설계의 제약
   - 레코드 크기 한도, 로드 순서(kPreLoadGame / kPostLoadGame / TESLoadGameEvent), 새 게임과 로드를 구분하는 방법

5. 성능: 4000개 넘는 플러그인 환경에서 이벤트 싱크의 부담을 줄이는 패턴(락 없는 큐, 파일 쓰기 스레드 분리 등)

6. 구독 CLI headless 실행(가장 중요). Claude Code, OpenAI Codex CLI, Gemini CLI 각각에 대해:
   - 구독 로그인 상태로 비대화형 1회 실행하는 정확한 명령과 옵션(현재 공식 문서 기준, 확인한 날짜 표기)
   - 모든 도구(파일 읽기·쓰기, 셸, 웹)를 끄고 순수 텍스트 생성만 하게 만드는 옵션, 그리고 샌드박스 옵션
   - 긴 입력을 stdin이나 파일로 넘기는 방법, 출력을 텍스트나 JSON으로 받는 방법, 종료 코드와 오류 구분
   - 로그인 여부와 설치 여부를 확인하는 방법, 구독 플랜별 사용량 한도
   - 서드파티 프로그램(게임 모드)이 사용자의 로그인된 CLI를 대신 실행하는 것이 각 회사 약관이나 사용 정책상 허용되는지

7. Windows에서 게임 프로세스(SKSE DLL)가 자식 프로세스를 실행할 때의 주의점
   - 창을 숨기는 방법(CREATE_NO_WINDOW), 게임 종료 시 처리(Job Object 등)
   - Node 기반 CLI의 PATH 탐색, 백신 오탐 사례

8. 게임 내 읽기 UI 비교(새 항목). 후보는 다음과 같다.
   - SKSE Menu Framework(ImGui 기반)
   - Prisma UI(Ultralight HTML/CSS/JS)
   - Scaleform SWF 직접 제작 또는 SkyUI 저널에 탭 주입
   - 바닐라 BookMenu에 런타임으로 텍스트를 넣는 방식
   - 그 밖에 조사 중 찾은 후보
   각 후보를 다음 기준으로 표로 비교해라.
   - 한글 렌더링과 폰트 지정 방법, 수만 자 분량 텍스트의 스크롤과 페이지 넘김, 문단과 제목 같은 서식 표현력
   - 텍스트 입력(캐릭터 시트 편집, 긴 결과 붙여넣기)과 클립보드 지원
   - 게임패드 지원, 메뉴가 열려 있을 때 게임 일시정지, 단축키로 열기
   - 성능(메뉴를 닫았을 때의 상시 비용 포함), SE 1.5.97 / AE 1.6.x / VR 지원 범위
   - Nexus 사용자층(다운로드 수, 유지보수 상태), 라이선스(무료 배포 모드에 써도 되는지, 재배포 조건)
   - C++ 쪽 연동 API의 형태와 난이도
   마지막에 이 모드에 맞는 추천안과 근거를 써라. 필수 의존성을 줄이는 대안(예: 기본은 가벼운 UI, 선택적으로 고급 UI)도 검토해라.

9. Nexus 배포 조건(새 항목)
   - 외부 AI 서비스나 CLI를 호출하는 모드에 대한 Nexus 정책, AI 생성 콘텐츠 표기 규정
   - 성인 콘텐츠: 본 모드는 일반 등급으로 두고 성인 지원만 별도 파일이나 별도 애드온으로 나누는 것이 정책상 필요한지 또는 관례인지. SkyrimNet, CHIM, Mantella 같은 AI 모드는 이 문제를 어떻게 처리하는지
   - SE / AE / GOG / VR 동시 지원을 위한 CommonLibSSE-NG 빌드 설정과 주의점

10. 성인 콘텐츠 지원(새 항목)
   - SexLab P+ 2.17 NG와 OStim NG가 장면 시작·종료·참여자 정보를 내보내는 방법(ModEvent 이름, 인자, Papyrus 또는 C++ API). 하드 의존성 없이 소프트 연동하는 방법
   - Claude, ChatGPT, Gemini 각각의 성인 창작물 정책. 구독 채팅과 CLI headless 실행에서 노골적 묘사 요청이 어떻게 처리되는지(거부, 완화, 허용). 근거는 공식 정책 문서 기준으로 하고, 확인한 날짜를 표기해라
   - 거부 응답을 자동으로 감지하고 "암시만" 수준으로 다시 요청하는 일반적인 방법

11. 기존 사례: SkyrimNet(MinLL)의 이벤트 캡처 방식과 외부에서 데이터를 읽는 API. 그 밖에 자동 플레이 기록·연대기·일기를 만드는 Skyrim 모드나 다른 게임 모드 사례
