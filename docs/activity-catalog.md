# 플레이 활동 전체 목록과 기록 여부

- 판: v0.3 (2026-11-08)
- v0.3에서 바뀐 것: 0단계 계측 결과([stage0-results.md](stage0-results.md))를 반영했다. 바뀐 행에는 **(v0.3)** 표시를 붙였다. 17절은 실측 신호표로 다시 썼다.
- 목적: 게임 플레이에서 일어나는 활동을 빠짐없이 나열하고, 각각 기록할지 정한다. 이 목록이 설계 초안 4.2와 4.3의 기준이다.
- v0.2에서 바뀐 것
  - 사용자 결정 A~E를 반영했다.
  - Codex 기술 검증과 아르곤 이야기 검토를 반영했다. 정리는 [reviews/activity-catalog-v0.1-triage.md](reviews/activity-catalog-v0.1-triage.md)에 있다.
  - 바뀐 행에는 **(v0.2)** 표시를 붙였다.
- 소스 이름은 CommonLibSSE-NG 로컬 헤더로 확인한 것이다. "폴링"은 이벤트가 없어서 주기적으로 상태를 읽는 방식이다. "0단계"라고 적힌 항목은 실제 게임에서 확인해야 한다. 헤더에 있다는 것과 실제 게임에서 그 의미로 발화한다는 것은 다르다.

## 원칙: 보관과 전달을 나눈다 (v0.2)

사용자 요구는 "모든 활동을 세세하게"다. 그래서 v0.1의 "묶음(합계만 남김)"을 두 층으로 나눴다.

| 층 | 하는 일 |
|---|---|
| **보관** | 플레이어와 관련된 관측은 원시 그대로 모두 남긴다. 봉인 조각은 압축해서 저장한다. 버리는 것은 detail 예산을 넘은 경우뿐이고, 버렸다는 사실과 개수를 기록한다. |
| **전달** | AI에게 넘길 때만 묶는다. 묶는 규칙은 설계 초안 7.4(전투 기록지 등)를 따른다. 보스전처럼 중요한 장면은 원시 기록을 더 많이 넘긴다. |

**관측은 층으로 나눈다.** 공격 하나는 시도 → 충돌(적중) → 효과 → 피해 → 사망의 여러 관측으로 남는다. 관측끼리의 연결에는 확신도를 붙이고, 연결되지 않은 관측도 버리지 않는다.

## 결정 표시

| 표시 | 뜻 |
|---|---|
| **기록** | MVP에서 하나하나 보관하고, 장면 재료로 넘긴다. |
| **2차** | 기록하지만 MVP 다음 단계에서 넣는다. |
| **묶음** | 하나하나 보관하되, AI에게는 횟수와 합계로만 넘긴다. |
| **안 함** | 수집하지 않는다. |
| **추정** | 기록하지만 근거가 간접적이라 "추정"으로 표시한다. 소설에서는 단정하지 않는다. |

## 판단 기준

1. **이야기 값**: 소설의 장면이나 인물에 쓰일 수 있는가.
2. **근거**: 믿을 만한 소스가 있는가. 없으면 추정으로 표시하거나 기록하지 않는다.
3. **비용**: 게임 성능과 저장 용량에 부담이 되는가.
4. **오염**: 플레이가 아닌 조작(콘솔, 설정, 메뉴 탐색)이 이야기로 섞이는가.

## 16. 습관 카운터 (v0.2, 아르곤)

습관은 기록을 쌓아야 보인다. 그래서 EXE가 계보를 따라 누적 횟수를 집계해 패키지 머리에 넣는다. 5회 이상일 때만 "습관"으로 넘기고, 처음 한두 번을 성격으로 단정하지 않는다.

| 습관 | 집계하는 기록 |
|---|---|
| 늘 묵는 여관, 늘 쉬는 곳 | 잠, 기다림의 장소 |
| 기도하는 신 | 축복 효과 적용 |
| 주력 무기와 주문 | 공격 시도와 적중의 무기·주문 |
| 위기 때의 대응 | 위기 직후의 포션, 회복 주문, 후퇴 |
| 동료를 대하는 방식 | 동료에게 건넨 물건과 착용 여부, 동료 명령 |
| 범죄 성향 | 훔치기, 소매치기, 자물쇠 따기 횟수 |
